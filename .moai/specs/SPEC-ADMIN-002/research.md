# SPEC-ADMIN-002 Research — 레거시 admin 재분석 (Playwright 실사 기반)

## 0. 배경 및 방법

기존 spec.md(v1.0.0, 2026-06-14)는 frontmatter에 `related-research: SPEC-ADMIN-002/research.md`를 명시했지만 실제 research.md가 존재하지 않았다 — 즉 레거시 admin을 실제 화면 단위로 열어 확인하지 않고 PHP 코드의 `disp*` 디스패치 함수명 인벤토리만으로 작성되었다. 이번 작업은 Playwright로 레거시 admin(`http://localhost:8080/`, admin 세션 유지 중)을 실제로 열어, **사용자가 지정한 7개 카테고리 순서**로 화면을 재확인하고, rhymix-ts 코드(`apps/web/app/admin/`)와 직접 대조했다.

**중요 발견**: 레거시 admin의 좌측 사이드바 구조 자체가 정확히 사용자가 요청한 7개 카테고리와 일치한다 — 즉 이 순서는 임의의 분류가 아니라 **레거시 Rhymix admin의 실제 1차 네비게이션 구조**다.

```
대시보드
사이트 제작/편집
회원
콘텐츠
즐겨찾기
설정
고급
```

rhymix-ts 현재 사이드바(`apps/web/components/admin/AdminSidebar.tsx`)는 이를 `대시보드 / 콘텐츠 / 사이트 설정 / 회원 / 시스템` 5개 그룹으로 재구성해 놓았다 — 레거시 IA와 1:1 대응되지 않아 기능 누락이 시각적으로도 드러나지 않는 구조적 문제가 있다.

- REQ-ADMIN2-020~031 (레이아웃 관리, 페이지 편집, 메뉴 DnD)은 기존 spec.md 내용과 정확히 일치. **추가 발견 없음**.

### 신규 REQ 후보

없음 (기존 REQ-ADMIN2-020~031로 충분히 커버됨). 단, REQ-ADMIN2-053의 우선순위를 P3→P2로 재검토할 가치가 있음 (레거시에서는 "준비중"이 아니라 1차 탭으로 노출됨).

## 3. 회원

### 레거시 인벤토리 (legacy-members-list.png, legacy-members-groups.png)

- **회원 목록**: 필터 탭(모든 회원/최고 관리자/승인/거부/미인증), 간단보기·상세보기 토글, 회원 추가/수정/삭제 버튼, 컬럼(아이디/이메일/이름/닉네임/상태/가입일/최근 로그인/회원 그룹/조회·수정), 그룹별·아이디별 검색.
- **회원 그룹**: 그룹 제목(인라인 편집) + 설명 + 기본그룹 라디오 + 그룹별 삭제, "추가" 링크로 그룹 신설, 그룹 이미지 마크 사용 여부 토글.

### rhymix-ts 구현 상태

- 회원 목록(`/admin/members`)은 구현됨. 회원 그룹(`/admin/members/groups`)은 **사이드바에 `disabled: true`로 "준비중"** — REQ-ADMIN2-040~043으로 정의되어 있어 **신규 발견 없음, 기존 REQ 정확함**.
- 회원 목록의 "최고 관리자/승인/거부/미인증" 상태 필터 탭은 spec.md에 명시적 REQ 없음 (REQ-ADMIN2-040대는 그룹 관리, 044대는 등록 위주).

### 신규 REQ 후보

- **REQ-ADMIN2-CAND-C1**: 회원 목록 페이지에 상태 필터(전체/최고관리자/승인/거부/미인증)를 탭 형태로 제공. (legacy: 회원 목록 상단 필터)

## 4. 콘텐츠

### 레거시 인벤토리 (legacy-content-boards.png, -documents.png, -comments.png, -content-files.png)

- **게시판 관리**: 번호/모듈 분류/도메인·URL/브라우저 제목/특이사항/등록일/편집(설정·복사·삭제) 컬럼, 모듈 이름 검색.
- **문서**: 탭(문서 목록/기본 설정/신고 목록). 목록은 상태 필터(전체/공개/비밀/임시/신고 목록), 간단보기·상세보기, 휴지통·삭제·이동·복사 일괄 작업, 컬럼(제목/글쓴이/조회수/추천/날짜/IP주소/상태).
- **댓글 관리**: 탭(댓글 목록/신고 목록), 상태 필터(전체/공개/비밀/대기/발행), 휴지통·삭제·발행중지·발행 일괄 작업.
- **파일 관리**: 탭(첨부 파일 목록/파일 업로드 설정/파일 다운로드 설정/기타 설정), 상태 필터(전체/유효/대기), 파일 크기·이미지 크기·다운로드·작성자·날짜·IP·상태·편집 컬럼.

### rhymix-ts 구현 상태

- 게시판 관리(`/admin/modules`) 구현됨.
- 전체 문서/댓글 관리는 REQ-ADMIN2-070~077로 이미 상세 정의(필터/일괄작업/신고 포함) — **일치**. 단, 문서 상태 필터에 "임시" 상태가 spec.md에 명시되지 않음 — 임시저장 문서도 관리 대상에 포함되어야 함을 명확히 할 필요.
- 파일 관리는 REQ-ADMIN2-078~082로 이미 다뤄짐 — 탭 구조(목록/업로드설정/다운로드설정/기타설정)까지 정확히 일치. **추가 발견 없음**.

### 신규 REQ 후보

- **REQ-ADMIN2-CAND-D1**: 전체 문서 관리 목록의 상태 필터에 "임시"(완료되지 않은 자동저장본)를 포함. (REQ-ADMIN2-070 보강)

없음. 기존 구현으로 충분.

## 6. 설정

### 레거시 인벤토리 — "시스템 설정"은 8개 탭으로 구성 (legacy-settings-general.png, -security.png, -seo.png)

| # | 탭 | 확인된 필드/항목 |
|---|---|---|
| 1 | 사이트 설정 | 사이트 제목/도메인/HTTPS/메인모듈/메인문서, 새 도메인 추가, 멀티도메인 미설정 도메인 처리 정책(301/302/접속허용/404) |
| 2 | 알림 설정 | (미확인 — 탭 존재만 확인) |
| 3 | 보안 설정 | 외부 멀티미디어 허용 도메인 목록, HTML class 허용 목록, 로봇 user-agent 목록, 관리자 로그인 허용/금지 IP, 자동 로그인 유지 기간(1~400일) + 보안키 갱신, SSL 전용 세션/쿠키 사용 |
| 4 | 고급 설정 | (미확인 — 탭 존재만 확인) |
| 5 | 디버그 설정 | (미확인 — 탭 존재만 확인) |
| 6 | SEO 설정 | 메인화면/서브페이지/개별문서 제목 템플릿($SITE_TITLE 등 변수), SEO 키워드/설명, OpenGraph·트위터 메타태그 사용 여부, 본문에서 설명/이미지/해시태그 추출 여부, 글 작성자명·작성시각 표시 여부 |
| 7 | 비동기 작업 | (미확인 — 탭 존재만 확인) |
| 8 | 사이트 잠금 | (미확인 — 탭 존재만 확인) |

### rhymix-ts 구현 상태 (코드 직접 대조: `apps/web/app/admin/settings/*`, `apps/web/app/admin/site/*`)

실제 라우트: `/admin/settings/site`, `/admin/settings/export`, `/admin/settings/import`, `/admin/site/design`, `/admin/site/mail`, `/admin/site/points` 만 존재.

| 레거시 탭 | rhymix-ts 대응 | 상태 |
|---|---|---|
| 사이트 설정 | `/admin/settings/site` | **구현됨** |
| 알림 설정 | REQ-ADMIN2-110~112 (`/admin/settings/notification`) | **미구현** (REQ는 정의됨, 라우트 없음) |
| 보안 설정 | REQ-ADMIN2-113~115 (`/admin/settings/security`) | **미구현** (REQ는 정의됨, 라우트 없음) |
| 고급 설정 | REQ-ADMIN2-116 (`/admin/settings/advanced`) | **미구현** |
| 디버그 설정 | REQ-ADMIN2-117 | **미구현** |
| SEO 설정 | REQ-ADMIN2-118~119 (`/admin/settings/seo`) | **미구현** |
| 비동기 작업 | spec.md에 **REQ 자체가 없음** | **누락 — 신규 REQ 필요** |
| 사이트 잠금 | install 단계에서만 설정 가능(`app/install/admin-config/admin-config-form.tsx`), **런타임 admin UI 없음** | **부분 — install-time만 존재, 신규 REQ 필요** |

기존 spec.md가 "설정 8개 서브메뉴 중 일부만 구현"이라는 결론은 정확하다 — 다만 **6개 탭은 이미 REQ가 정의되어 있고 실제 코드만 없는 상태(설계 완료, 구현 대기)**이며, 신규로 발견된 갭은 "비동기 작업"과 "사이트 잠금 런타임 UI" 2건뿐이다.

### 신규 REQ 후보

- **REQ-ADMIN2-CAND-F1**: `/admin/settings/async`에 비동기 작업 큐 상태(대기/처리중/실패 건수)와 즉시 실행 버튼을 제공하는 비동기 작업 설정 페이지. (legacy: 비동기 작업 탭)
- **REQ-ADMIN2-CAND-F2**: `/admin/settings/sitelock` 런타임 UI 추가 — 현재 install 단계 1회 설정만 가능한 사이트 잠금(점검 모드 + 허용 IP)을 운영 중에도 토글할 수 있도록 함. (legacy: 사이트 잠금 탭, `dispAdminConfigSitelock`)

## 7. 고급

### 레거시 인벤토리 (legacy-advanced-autoinstall.png, -addons.png, -trash.png, -counter.png, -tags.png)

- **쉬운 설치**: 전체(1341)/Installed(8)/설정 탭. **프로그램** 5종 — 모듈(171)/애드온(322)/위젯(173)/에디터컴포넌트(20)/단락에디터컴포넌트(3). **스킨** 8종 — 레이아웃(256)/모바일 레이아웃(12)/모듈 스킨(128)/모듈 모바일 스킨(23)/위젯 스킨(149)/위젯 스타일(33)/에디터 스타일(10)/회원레벨 아이콘(40). 즉 **13개 카테고리**의 원격 마켓플레이스(신규 등록/다운로드/인기 정렬, 검색).
- **설치된 애드온**: 전체 6개, PC/Mobile 체크박스로 개별 활성화, 설정 링크.
- **휴지통으로 이동**: 휴지통비우기 타입(문서/댓글), 삭제/복원, "휴지통 비우기" 버튼 + 경고 문구.
- **접속 통계 관리**: 전체현황(오늘 Visitor/Pageview), 시간대별/일별/월별/연도별 탭.
- **태그**: 태그 구분 방법(쉼표/해시/공백 다중 선택).

### rhymix-ts 구현 상태 (코드 직접 대조)

| 레거시 기능 | rhymix-ts 대응 | 상태 |

### 신규 REQ 후보

- **REQ-ADMIN2-CAND-G1**: 마켓플레이스형 "쉬운 설치"는 npm 패키지 기반 아키텍처와 충돌하므로 직접 포팅하지 않음. 대신 `/admin/addons`에 "신규 애드온 추가 가이드"(npm install 안내 + package.json 등록 절차) 링크만 노출. **(영구 제외 후보 — REQ-ADMIN2-FTP와 동일한 처리 방식 권장, 사용자 확인 필요)**

## 신규 발견 사항 요약

기존 spec.md(149개 REQ)는 실제로 매우 포괄적이며, 코드 대조 결과 **대부분의 "갭"은 이미 REQ로 정의되어 있고 구현만 대기 중인 상태**였다. 진짜 신규 발견(기존 spec.md에 전혀 없던 것)은 다음 8건이다:

1. **REQ-ADMIN2-CAND-A1** — 관리자 메뉴 초기화 (대시보드 footer)
2. **REQ-ADMIN2-CAND-A2** — 세션 정리 (대시보드 footer)
3. **REQ-ADMIN2-CAND-C1** — 회원 목록 상태 필터 탭(승인/거부/미인증 등)
4. **REQ-ADMIN2-CAND-D1** — 문서 관리 "임시" 상태 필터 보강
5. **REQ-ADMIN2-CAND-F1** — 비동기 작업 설정 페이지 (설정 8개 탭 중 유일하게 REQ 자체가 없던 항목)
6. **REQ-ADMIN2-CAND-F2** — 사이트 잠금 런타임 admin UI (현재 install-time 전용)
7. **REQ-ADMIN2-CAND-G1** — 쉬운 설치(마켓플레이스) 처리 방향 결정 필요 (영구 제외 후보, 사용자 확인 필요)
8. **REQ-ADMIN2-CAND-G2** — 태그 구분 방법 설정

또한 **정정 사항**: 1차 탐색 보고에서 "휴지통 누락"이라 했던 것은 코드 확인 결과 오류로, `/admin/trash`는 이미 구현되어 있다.
