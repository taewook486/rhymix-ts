# SPEC-ADMIN-002 — Acceptance Criteria

모든 시나리오는 Given-When-Then 형식이다. Phase별로 그룹화하며, 각 Slice 완료의 1차 신호는 **좌측 admin 메뉴에서 해당 항목의 "준비중" 표기가 사라지고 화면이 동작**하는 것이다.

---

## Phase 1 (P1) 시나리오

### AC-1: 대시보드 위젯 (REQ-ADMIN2-001~003, 007)

- **Given** 게시판에 문서·댓글이 존재하는 사이트, **When** 관리자가 `/admin`을 연다, **Then** 최근 문서 10건과 최근 댓글 10건 위젯이 제목·작성자·시간과 함께 표시되고 각 항목이 원본으로 링크된다.
- **Given** 댓글 위젯 데이터 조회가 실패한다, **When** 대시보드가 렌더된다, **Then** 댓글 위젯만 에러 상태로 표시되고 나머지 위젯(문서·통계)은 정상 렌더된다.

### AC-2: 페이지 모듈 (REQ-ADMIN2-025, 026)

- **Given** 페이지 모듈 인스턴스가 존재한다, **When** 관리자가 `/admin/pages`를 연다, **Then** "준비중" 대신 페이지 목록이 표시된다.
- **Given** 한 페이지를 편집한다, **When** mcontent를 수정하고 저장한다, **Then** 변경이 영속되고 공개 페이지에 반영되며, revert로 직전 상태 복원이 가능하다.

### AC-3: 회원 그룹 + 직접 등록 (REQ-ADMIN2-040~045)

- **Given** 기본 그룹이 1개 존재한다, **When** 관리자가 새 그룹을 생성하고 "자동 배정" 플래그를 켠다, **Then** 기존 기본 그룹의 자동 배정이 해제되어 항상 정확히 1개의 기본 그룹이 유지된다.
- **Given** 멤버가 배정된 그룹을 삭제한다, **When** 삭제를 확정한다, **Then** 해당 멤버들이 기본 그룹으로 재배정되고 AdminLog에 기록된다.
- **Given** 관리자가 `/admin/members/new`에서 이메일·비밀번호·닉네임·그룹을 입력한다, **When** 제출한다, **Then** 회원이 생성되고 비밀번호는 해시로만 저장되며 평문이 로그에 남지 않는다.

### AC-4: 회원 설정 탭 (REQ-ADMIN2-046~048, 050)

- **Given** `/admin/members/settings`를 연다, **When** 가입 탭에서 "이메일 인증 필수"를 켜고 저장한다, **Then** 공개 가입 플로우가 이메일 인증을 요구한다.
- **Given** 약관 탭에서 이용약관을 편집한다, **When** 저장한다, **Then** 가입 화면에 갱신된 약관이 노출된다.

### AC-5: 전체 문서/댓글 관리 (REQ-ADMIN2-070, 071, 075, 076)

- **Given** 여러 게시판에 문서가 있다, **When** 관리자가 `/admin/documents`에서 mid·작성자·검색어로 필터한다, **Then** 일치하는 문서만 표시된다.
- **Given** 문서 다건을 선택한다, **When** "휴지통 이동" 일괄 작업을 실행한다, **Then** 선택 문서가 트랜잭션으로 처리되고 AdminLog에 기록된다.
- **Given** 댓글 다건을 선택한다, **When** 일괄 삭제한다, **Then** 대댓글까지 cascade 삭제되고 기록된다.

### AC-6: 알림 + 보안 설정 (REQ-ADMIN2-110, 113, 114)

- **Given** `/admin/settings/notification`을 연다, **When** 발신자 주소와 SMTP 설정을 저장한다, **Then** 설정이 SmtpMailDispatcher에 반영된다.
- **Given** 보안 설정에서 세션 수명을 범위 밖 값(예: 0 또는 음수)으로 입력한다, **When** 저장을 시도한다, **Then** 검증 에러로 거부되고 인증 우회 설정이 저장되지 않는다.

## Phase 2 (P2) 시나리오

### AC-7: 파일 관리 (REQ-ADMIN2-078, 079)

- **Given** 업로드된 파일이 있다, **When** `/admin/files`에서 목록을 본다, **Then** 이름·크기·업로더·연결 문서·다운로드 수가 표시된다.
- **Given** 일부 파일이 어떤 문서/댓글에도 연결되지 않았다, **When** 고아 파일 정리를 dry-run으로 실행한다, **Then** 삭제 대상 미리보기가 표시되고 확정 전까지 실제 삭제가 일어나지 않는다.

### AC-8: 스팸필터 (REQ-ADMIN2-120~122)

- **Given** 금지어가 등록되어 있다, **When** 사용자가 금지어 포함 댓글을 제출한다, **Then** 제출이 스팸 필터 에러로 거부되고 내용이 저장되지 않는다.
- **Given** 차단 IP가 등록되어 있다, **When** 해당 IP에서 문서를 제출한다, **Then** 제출이 거부된다.

### AC-9: 통계 (REQ-ADMIN2-140~142)

- **Given** 사이트에 방문 트래픽이 있다, **When** 관리자가 `/admin/stats`를 연다, **Then** 일별/월별 방문 차트가 표시된다.
- **Given** 공개 페이지가 요청된다, **When** 방문 카운트가 증가한다, **Then** 페이지 렌더가 카운팅으로 인해 차단되지 않으며 raw IP는 해시/절단되어 저장된다.

### AC-10: SEO (REQ-ADMIN2-118, 119)

- **Given** SEO 설정에서 sitemap 생성을 켜고 저장한다, **When** `sitemap.xml`을 요청한다, **Then** 공개 문서·페이지를 반영한 sitemap이 응답된다.

### AC-14: 회원 디자인 설정 (REQ-ADMIN2-053)

- **Given** `/admin/members/settings`의 디자인 탭을 연다, **When** 회원 영역 스킨/템플릿을 선택하고 저장한다, **Then** 선택이 영속되고 회원 영역 렌더에 반영되며 좌측 메뉴에서 "준비중" 표기가 사라진다.

### AC-15: admin 전역 유틸리티 — 메뉴 초기화 / 세션 정리 (REQ-ADMIN2-150, 151)

- **Given** admin 메뉴가 캐시되어 있다, **When** 관리자가 footer의 "관리자 메뉴 초기화"를 실행한다, **Then** 메뉴 캐시가 무효화되고 다음 요청에서 재생성되며 AdminLog에 기록된다.
- **Given** 만료 세션과 현재 관리자의 활성 세션이 공존한다, **When** "세션 정리"를 실행한다, **Then** 만료 세션만 삭제되고 삭제 건수가 보고되며 현재 관리자 세션은 종료되지 않는다.

### AC-16: 회원 목록 상태 필터 (REQ-ADMIN2-152)

- **Given** 승인/거부/미인증 상태의 회원이 섞여 있다, **When** `/admin/members`에서 "미인증" 필터 탭을 선택한다, **Then** 미인증 회원만 목록에 표시된다.

### AC-17: 문서 "임시" 상태 필터 (REQ-ADMIN2-070, 153)

- **Given** 자동저장된 임시 문서가 존재한다, **When** `/admin/documents`의 상태 필터를 "임시"로 설정한다, **Then** 임시 문서만 표시되고 삭제 또는 복구가 가능하다.

### AC-18: 비동기 작업 (REQ-ADMIN2-154)

- **Given** 대기·처리중·실패 상태의 비동기 작업이 있다, **When** `/admin/settings/async`를 연다, **Then** 상태별 건수가 표시되고 "즉시 실행"으로 대기 작업을 처리할 수 있다.

### AC-19: 사이트 잠금 런타임 UI (REQ-ADMIN2-155)

- **Given** 운영 중인 사이트, **When** 관리자가 `/admin/settings/sitelock`에서 점검 모드를 켜고 허용 IP를 추가한다, **Then** 비허용 IP의 공개 페이지 접근이 차단되되 현재 관리자의 admin 접근은 유지된다.

## Phase 3 (P3) 시나리오

### AC-11: 설문 (REQ-ADMIN2-083~085)

- **Given** 관리자가 설문을 생성한다, **When** 질문·옵션·기간을 저장한다, **Then** `/admin/polls` 목록에 표시되고 결과 화면에서 옵션별 득표수·비율이 보인다.

### AC-12: 서버 환경 (REQ-ADMIN2-144, 145)

- **Given** `/admin/system/server-env`를 연다, **When** 화면을 본다, **Then** Node/Next.js/DB 버전 등 런타임 정보가 표시되되 DB 비밀번호·API 키·세션 시크릿은 마스킹된다.

### AC-13: 닉네임 이력 (REQ-ADMIN2-056, 057)

- **Given** 회원의 닉네임이 변경된다, **When** `/admin/members/nickname-log`를 본다, **Then** 이전/이후 닉네임과 시각이 기록으로 표시된다.

### AC-20: 태그 구분 방법 설정 (REQ-ADMIN2-156)

- **Given** 태그 설정에서 구분 방법을 "해시(#)"로 지정한다, **When** 해시로 구분된 태그가 포함된 문서를 저장한다, **Then** 해당 구분 규칙으로 태그가 파싱·등록된다.

## Edge Cases

- 대시보드 위젯 중 하나의 조회 실패가 전체 대시보드를 막지 않는다(AC-1).
- 마지막 기본 그룹은 삭제 불가, 또는 삭제 시 다른 그룹이 기본으로 승격되어 항상 1개 기본 그룹 보장(AC-3).
- 비밀번호 평문이 어떤 로그·AdminLog·에러 메시지에도 남지 않는다(AC-3, REQ-ADMIN2-045).
- 일괄 작업 중 일부 항목 실패 시 트랜잭션 롤백 또는 부분 실패 보고 정책이 일관된다(AC-5, AC-7).
- 시크릿/PII가 서버환경·통계 어디에서도 평문 노출되지 않는다(AC-9, AC-12).
- 잘못된 보안 설정 값은 저장 전에 거부된다(AC-6).
- 세션 정리(151)는 현재 관리자의 활성 세션을 절대 삭제하지 않는다(AC-15).
- 사이트 잠금 런타임 토글(155) 시 현재 관리자가 자기 자신을 잠가 admin 접근 불가가 되지 않는다(AC-19).

## Quality Gate / Definition of Done

각 Slice는 다음을 모두 충족할 때 완료로 간주한다.

- [ ] 해당 좌측 admin 메뉴 항목의 "준비중" 표기 제거 및 화면 동작
- [ ] Slice에 속한 REQ의 acceptance 시나리오 통과
- [ ] 변경 행위가 AdminLog에 기록됨(해당 REQ에 한해)
- [ ] `requireAdmin` 가드 우회 없음(인가 테스트 포함)
- [ ] 시크릿/PII 노출 없음(해당 REQ에 한해)
- [ ] TRUST 5 품질 게이트 통과(테스트 85%+, lint/type 0 에러)
- [ ] @MX 태그 부착(일괄 처리/통계/보안 검증/마스킹 지점)
- [ ] 신규 테이블 도입 시 Prisma migration 포함
