제품 코드 변경이 없다. 산출물은 이 SPEC 문서 3개(spec/plan/acceptance)와 `INDEX.md` 갱신,
그리고 영역 SPEC 001~010 이 따를 규약이다. v0.2.0 은 점검 보고서

## §1. 파일별 변경 계획

결정이 뒤집힐 가능성이 큰 것부터 적는다.

### M1 — 영역 재편과 범위 확장 (REQ-LGP-001·003, spec.md §2.3)

- 영역 경계를 GNB 위치에서 소속 모듈로 바꾼다. 영역 SPEC 은 6개에서 10개(007 메일·알림,
  008·009 방문자, 010 비-UI 판정표 신설)가 된다.
- 판정 대상 목록의 SSOT 를 `module.xml` 선언 액션으로, 판정 단위를 고유 act 로 고정한다.
- 판단이 들어간 배분: 방문자 보조 팝업 15개(widget·module·page·layout·message·krzip·menu)는 006 이,
  importer·krzip·autoinstall 은 화면은 006, 기능 지원 여부는 010 이 판정한다. 영역 SPEC 작성 때
  이 배분이 맞지 않으면 본 SPEC 을 먼저 개정한다(REQ-LGP-001).
- 상태: 본 개정에서 완료.

### M2 — 근거·기준선 규칙 보강 (REQ-LGP-002·007·008·009)

- 레거시 DB 시드는 덤프·복원을 거쳐서만 허용(REQ-LGP-009).

## §2. 영역 SPEC 착수 순서와 의존

```
000 (규약, 본 SPEC, v0.2.0)
 ├─ 001 사이트 제작/편집            ✅ completed (MENU-001 superseded 전환 완료)
 └─ 002 회원                        ← MEMBER-PARITY-001 재검증
     └─ 003 콘텐츠                  ← CONTENT-PARITY-001 흡수 (관리자 act 36, 가장 큼)
         └─ 004 즐겨찾기 UI          ← ADMIN-MENU-PARITY-001 재검증
             └─ 005 설정             (시스템 설정 7 포함)
                 └─ 006 고급          (관리자 act 46 + 방문자 보조 팝업 15)
                     └─ 007 메일·알림  (advanced_mailer 9 + ncenterlite 8)
                         └─ 008 방문자 — 회원 셀프서비스
                             └─ 009 방문자 — 게시판·문서·댓글·커뮤니케이션
                                 └─ 010 비-UI 판정표 ("의도적 제외"는 사용자 확인 필수)
```

순차 의존은 기술적 의존이 아니라 **작업 순서 약속**이다. 다만 다음 두 가지는 실제 선행 조건이다.

- 003 은 `CONTENT-PARITY-001`(in-progress)을 흡수하므로 착수 전에 그 SPEC 의 잔여 AC 를 확정해야 한다.
- 006 의 importer·krzip·autoinstall 행은 010 의 판정을 인용하므로, 010 판정이 나오기 전에는 해당 행을
  잠정 판정으로 둔다.
